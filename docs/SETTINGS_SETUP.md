# 基本情報設定画面 ─ 導入手順

管理画面に「基本情報設定」タブを追加し、**申し込みや登録が入ったときの通知先メールアドレス**を
マネージャーが自分で設定できるようにするための手順です。

作業は10分ほどで、スプレッドシートの中身には触りません。

---

## これで何ができるようになるか

**いままで**：公演の申し込みが入っても、メールが届くのは申込者本人だけでした。
事務所側は管理画面を開くまで気づけません。

**これから**：申し込みが入った瞬間に、設定したアドレスへ通知が届きます。
宛先は管理画面から、いつでも変更できます。複数人に同時に送れます。

設定できるのは次の項目です。

| 分類 | 項目 |
|---|---|
| 通知先 | 公演の申し込み／サポーター登録／システムエラー の各通知先、通知のオンオフ |
| 基本情報 | 事務所名、問い合わせ先メール、問い合わせ先電話、サイトURL、LINE URL |
| 運用 | 申し込み確認メールに添える一文 |

---

## 手順

### 1. GAS に新しいファイルを追加する

1. [Google Apps Script](https://script.google.com) を開き、このサイトのプロジェクトを開きます
2. 左の **ファイル** の横にある **＋** → **スクリプト** を選びます
3. 名前を `settings_addition` にします（`.gs` は自動で付きます）
4. `gas/settings_addition.gs` の中身を**まるごと**貼り付けます

### 2. 既存ファイルを差し替える

`gas/supporter-registration.gs` に4箇所の追記を入れてあります。
GAS 側の `supporter-registration` を開き、**中身を全部消してから**、
このリポジトリの `gas/supporter-registration.gs` を丸ごと貼り付けてください。

追記した箇所は次の4つです（自分で入れる場合の参考）。

| 場所 | 内容 |
|---|---|
| `doGet` の `getMembers` の直後 | `getSettings` の分岐を追加 |
| `doPost` の `deleteEvent` の直後 | `saveSettings` の分岐を追加 |
| `submitReservation` の `return` の直前 | `notifyReservation_()` の呼び出し |
| `completeRegistration` の `return` の直前 | `notifyMemberRegistered_()` の呼び出し |

### 3. デプロイし直す（ここを飛ばすと反映されません）

**GAS はコードを保存しただけでは公開URLに反映されません。** 必ず次をやってください。

1. 右上の **デプロイ** → **デプロイを管理**
2. 現在のデプロイの右にある **鉛筆（編集）** をクリック
3. **バージョン** を「**新バージョン**」に変更
4. **デプロイ** をクリック

> URL は変わりません。`admin.html` と `index.html` の `GAS_URL` を書き換える必要はありません。
> もし URL が変わってしまった場合は、**新しいデプロイを作ってしまっています**。
> 「デプロイを管理」から既存のものを編集し直してください。

### 4. 設定を入れる

1. `admin.html` を開いてログインします
2. 上のタブに **基本情報設定** が増えています
3. **公演の申し込みが入ったときの通知先** に、受け取りたいアドレスを入れます
   - 複数人に送るときは、カンマか改行で区切ります
   - 例：`manager@example.com, staff@example.com`
4. **設定を保存** を押します

`settings` シートがスプレッドシートに自動で作られ、そこに保存されます。
シートを直接編集しても構いません（管理画面と同じ結果になります）。

### 5. 届くか試す

GAS エディタで関数 **`testNotificationRecipients`** を選んで **実行** すると、
設定した宛先それぞれにテストメールが1通ずつ届きます。

実行ログに、どの通知先が設定済みでどれが空かが出ます。

---

## 覚えておいていただきたいこと

**通知先を空にすると、その通知は送られません。** エラーにはならず、静かに止まります。
「届かない」ときは、まず設定が空でないかを見てください。

**通知が送れなくても、申し込み自体は必ず成立します。** 通知の失敗でお客様の申し込みが
消えることはありません（そう作ってあります）。

**GmailApp の1日あたりの送信上限は100通です**（無料アカウントの場合）。
申込者への確認メールと通知メールの両方がこの枠を使います。
公演の直前など申し込みが集中する日は、通知先を絞ることも検討してください。

**項目を増やしたくなったら** `settings_addition.gs` の `SETTINGS_DEFINITION` に1行足すだけです。
管理画面は定義を読んで入力欄を描いているので、`admin.html` は触らなくて済みます。

---

## うまくいかないとき

| 症状 | 原因 |
|---|---|
| タブは出るが「設定を読み込めませんでした」 | 手順3のデプロイをやり直していない |
| 「ログインし直してください」と出る | パスワードが変わった、または24時間経過。一度ログアウトして入り直す |
| 保存しても値が戻る | GAS 側で検証に引っかかっている。メールアドレスの形式とURLの `https://` を確認 |
| テストメールが届かない | 宛先が空、または「通知メールを送る」がオフ。迷惑メールフォルダも確認 |
